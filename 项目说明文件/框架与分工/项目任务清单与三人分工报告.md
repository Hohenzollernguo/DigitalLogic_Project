# CS207 数字华容道项目：任务清单与三人分工报告

编制日期：2026-11-17。团队：A、B、C。开发语言：Verilog。

本报告依据项目目录内的官方文件制定，目标是覆盖完整评分功能，同时让三人可以并行开发。本文给出的是开发计划，并不表示电路已经实现或通过验收。

## 1. 结论与范围

建议采用 **EGO1 基础外设方案**：拨码开关与按键输入，8 位数码管与 16 个 LED 输出。先完成全部 70 分功能项，不把 VGA、UART、蓝牙或手机 APP 纳入本轮分工。官方允许选择高级外设，但没有在这份评分表中为其单列加分；而辅助提示、统计信息仍要求使用基础外设。

三人的主要职责如下：

| 成员 | 负责领域 | 独立交付物 | 如何不等待队友 |
|---|---|---|---|
| A | 游戏核心与状态管理 | 初始化、移动判定、棋盘更新、计数、通关、撤回 | 用 testbench 直接发送命令，检查状态数据，不需要真实按键或显示 |
| B | 显示系统与辅助提示 | 数码管驱动、显示排版、LED 映射、可移动棋子提示、状态灯 | 用固定棋盘和模拟状态驱动显示，不需要 A 的核心完成 |
| C | 输入控制、演示模式与集成 | 同步消抖、输入命令、演示序列、顶层连线、XDC、系统验证与交付组织 | 用模拟核心接口验证输入与演示，用测试图样先检查板卡引脚 |

**关键原则：棋盘、计数和游戏阶段只由 A 的核心维护；B 只读取状态；C 只发送命令。** 避免多个人分别维护一份“当前棋盘”或“当前步数”。接口约定完成后，三条开发线即可同时推进。

总工作量按设计、编码、测试、上板、资料和答辩准备综合估算，每人暂分配 40 个相对工作量点。工作量点不是课程分数，也不承诺精确工时；实际进度应定期复核。

## 5. 保证独立开发的模块接口

### 5.1 总体结构

```text
物理按键/拨码
      │
      ▼
C：输入处理、模式选择、演示序列、命令路由
      │ 统一命令                         │ 模式、展示切换、输出静默
      ▼                                  │
A：game_core                             │
      │ 棋盘、阶段、错误、统计             │
      └──────────────────┬───────────────┘
                         ▼
                 B：提示与显示系统
                         │
                    数码管、LED
```

顶层连线由 C 维护。实际依赖是“大家遵守接口”，不是“B 必须等 A 写完才能开始”。完整联调仍需全部模块到齐，因此要在开发早期搭建空壳接口并至少运行一次替身联调。

### 5.2 建议冻结的接口契约

以下是团队建议，不是官方强制端口命名。以 Verilog-2001 可使用的打包向量作为跨模块接口，避免把数组端口或语言版本差异带入集成。

| 信号/约定 | 建议定义 | 所有者/使用方 |
|---|---|---|
| `clk`、`rst` | 单一系统时钟；模块内部统一高有效复位；板上复位极性在输入层转换 | C 提供，全员使用 |
| `cmd_valid`、`cmd_ready` | 只在时钟上升沿且二者同时为 1 时接受一条命令；未接受前命令与载荷保持稳定 | C → A；A 回传 ready |
| `cmd_kind[2:0]` | `CLEAR=0`、`CONFIRM=1`、`UNDO=2`、`LOAD_DEMO=3`；其余保留并忽略 | 共同定义，C → A |
| `cmd_tile[3:0]` | 用户输入编号；保留 9～15，交由核心判非法，输入层不能偷偷截断到 0～8 | C → A |
| `cmd_board[35:0]` | 仅演示预装载命令使用；正常人工初始化仍逐格确认 | C → A |
| `board[35:0]` | 第 i 格为 `board[35-4*i -: 4]`，i=0～8，按行排列；胜利值 `36'h123456780` | A → B |
| `filled_count[3:0]` | 0～9；用于区分未输入位置和已输入的 0；初始化出错位为当前待填位置 | A → B |
| `phase[1:0]` | `INIT=0`、`PLAY=1`、`WON=2`、`STATS=3` | A → B/C |
| `init_error`、`move_error` | 核心维护的错误状态；B 只负责 E/全亮/闪烁表现 | A → B |
| `valid_count[CW-1:0]`、`invalid_count[CW-1:0]` | 两个计数的唯一来源；CW 及溢出策略统一决定，见 §8 | A → B |
| `undo_available` | 有可恢复快照时为 1；测试和控制可读取 | A → C/testbench |
| `view_toggle`、`view_reset` | 单周期显示切换脉冲及选择状态复位；B 维护奇偶选择状态 | C → B |
| `demo_mode`、`advanced_active` | 当前选择的模式、是否使用高级外设；基础方案后者恒为 0 | C → B |
| `output_blank` | 全部外部输出熄灭的覆盖信号，用于复位等待及演示末步；内部可保留模式选择 | C → B |
| `hint_mask[7:0]` | B 内部约定 bit7 对应棋子 1，bit0 对应棋子 8；未完成初始化时全 0 | B 内部/测试 |

时序约定：接受命令的上升沿更新核心寄存器，更新后的状态供显示层组合读取或下一拍采样。输入控制在等待接受时不重复生成同一事件；演示 FSM 以命令被接受为推进依据。复位取消待处理命令。B 不应把短暂组合变化当成新的游戏事件。

建议输入优先级为复位 > 模式切换清理 > 撤回 > 当前模式下的确认/演示推进。展示切换只改变视图，可以独立处理。所有按键“一次按下只产生一次操作”；长按是否重复不属于官方要求，基础方案采用不重复。

### 5.3 状态归属与撤回

A 保存当前棋盘、阶段、计数、错误和一份操作前快照。初始化成功后计数为 0；无效初始化不算游戏无效步数。`LOAD_DEMO` 装载完整演示棋盘并清零统计与历史，再进行通关判断。

建议单步撤回恢复“上一次移动尝试之前”的棋盘、两个计数及相应游戏状态；有效、无效移动均建立快照，展示切换不建立快照。恢复后清除快照有效位，防止连续按撤回在两个状态之间来回切换。此为对原文未详述部分的建议解释，最终以 §8 的澄清结果为准。

模式切换建议通过 `CLEAR` 清理旧游戏和历史，再进入对应入口；B 的显示选择也一起复位。不要让 C 绕开核心直接改棋盘或计数。

| 成员 | 独立测试方式 | 不必等待的真实模块 |
|---|---|---|
| A | testbench 发 CLEAR/CONFIRM/UNDO/LOAD_DEMO；直接检查 board、phase、计数和错误 | 按键、显示、演示控制器 |

## 6. IO 分配与硬件核对清单

官方固定的输出映射必须保留：

| 用途 | 从左到右的引脚 | 含义 |
|---|---|---|
| 提示 / 统计区 | F6、G4、G3、J4、H4、J3、J2、K2 | 提示依次对应棋子 1～8；统计前 4 位有效数、后 4 位无效数，各自高位在左 |
| 第 9 格 | K1、H6、H5、J5 | 棋子编号的 bit3～bit0；0 全灭，初始化错误全亮 |
| 高级外设灯 | K6 | 基础方案为灭 |
| 游戏模式灯 | L1 | 游戏模式时亮 |
| 演示模式灯 | M1 | 演示模式时亮 |
| 游戏状态灯 | K3 | 非法输入闪烁、通关长亮、其他状态灭 |

建议输入分配：4 个物理相邻拨码开关作为编号输入，另 1 个拨码开关选择模式；S0 确认、S1 展示切换、S2 撤回、S3 演示推进；S6 复位。S4 保留。除复位推荐位置外，这些按键用途是团队建议；C 应绘制实际板卡上的位置图，并核实拨码左右顺序。

硬件实现需要注意：

- EGO1 用户手册 §4 给出的时钟为 100 MHz，P17；时钟约束周期应与之对应为 10 ns。扫描、消抖和闪烁建议使用时钟使能，不把普通逻辑分频信号随意当成新时钟。
- 用户手册 §6.1 说明五个通用按键默认为低、按下为高；S6 的实际复位电平需单独核对，不因端口名写作 `sys_rst_n` 就直接推断。
- 用户手册 §6.3～6.4 说明 LED 高有效，数码管在 FPGA 侧的位选和段选也高有效。数码管是两组四位，有两组段选总线；B 的驱动和 C 的顶层/XDC 必须匹配。
- 配套 XDC 中 `led_pin[0]` 对应 F6，即提示区域物理最左灯。因此若逻辑提示采用 bit7=棋子1，需明确映射到这个物理端口，不能把整条向量直接接上后假设方向正确。
- XDC 示例中拨码端口索引与用户手册的 SW 编号并非直观一一同名，应按物理位置和管脚验证。
- 配套 XDC 带有大量未使用外设，并使用了斜线分隔文本。C 应生成项目专用、语法有效的 Tcl/XDC，只保留实际端口约束，把说明文字改为 `#` 注释，并补上时钟约束。

复位时按官方要求清空棋盘和统计；演示最后一步按原文要求让所有外部输出熄灭。建议用 `output_blank` 统一覆盖模式灯等输出，避免末步仍亮着演示灯。

## 7. 演示脚本与验收用例

### 7.1 建议采用官方示例作为演示 ROM/状态机内容

演示初始化可以用一条预装载命令完成。初始化完成后，每按一次演示推进键执行下一行操作，不自动连续播放。

| 步骤 | 核心命令/效果 | 棋盘 | 有效/无效数 | 提示棋子 | 状态 |
|---|---|---|---|---|---|
| 1 | 装载初始棋盘 | 123456708 | 0 / 0 | 5、7、8 | 正常，最后一个数码位为空白，第 9 格 LED 为 1000 |
| 2 | 移动棋子 1 | 不变 | 0 / 1 | 5、7、8 | 非法移动，K3 闪烁 |
| 3 | 移动棋子 8 | 123456780 | 1 / 1 | 6、8 | 通关，K3 长亮，先保留棋盘 |
| 4 | 模拟通关后确认 | 棋盘数据保持 | 1 / 1 | 可保留计算结果 | 数码管切到左右十进制统计 |
| 5 | 清理并覆盖所有输出 | 清空 | 0 / 0 | 不显示 | 全部输出熄灭 |

展示切换键仍可使用。演示的初始提示视图与“奇数次提示、偶数次统计”的关系见 §8。数字统计建议显示 `01` 和 `01`，中间四位空白；官方没有强制前导零样式。

演示控制应复用 A 的移动规则和计数、B 的显示，不再维护另一套游戏核心。A 因而需要尽早提供 `LOAD_DEMO` 接口；C 可以先对模拟核心验证命令序列。

### 7.2 最低测试矩阵

| 用例组 | 必测场景 | 主责 |
|---|---|---|
| 复位 | 初始化中、非法输入后、游戏中、通关后、统计页、演示中复位；棋盘/计数/历史不残留 | A；C 系统复核 |

## 8. 原文歧义、笔误及建议处理

这些事项需要团队先写成一致口径；涉及评分解释的部分由 C 汇总向 TA 核实。并不需要等所有答复才能开始开发：模块划分、基本接口、正常输入和 0～15 计数场景可以先完成。

| 问题 | 官方已知内容 | 建议及边界 |
|---|---|---|
| 计数超过 15 | 每类计数只分配 4 个 LED；数码管至少两位十进制，且要求数值一致（p2、p6） | 4 位只能表示 0～15，原文未定义溢出。不要擅自把低 4 位显示称为完整统计。先参数化计数接口，在 0～15 验证；请 TA 确认回绕、饱和或扩展显示口径。回绕/饱和都不能自行宣称满足无限次计数 |
| 撤回的“上一步” | 只说回到上一步，棋盘和统计同步撤回（p6） | 建议包括上一次有效或无效的移动尝试；只保留一级历史；不包括初始化输入、展示切换。是否允许通关后撤回也需确认；初版仅在 PLAY 接受撤回 |
| 演示计数笔误 | p6 第三步标题写“合法下棋”却写“无效步数统计+1”；p7 明确有效数 1、无效数 1 | 按 §3.5 正式移动规则和后续数值实现：第三步有效数加 1，无效数维持 1；在答辩资料注明该理解 |
| 视图初始状态 | p2 规定奇数次提示、偶数次统计；p6 演示初始又展示提示，之后描述按键看统计 | 建议普通游戏复位选择为统计，第一次切换为提示。演示初始可预置提示，但首次切换行为需统一确认；B 留可配置初始选择，C 的脚本和说明同步调整，不能分别采用相反假设 |
| 游戏时选 0 或 9～15 | 初始化范围明确；游戏阶段对这些输入未单列细则 | 建议视为无效移动：棋盘不变、无效数加 1、状态灯闪烁。不得把 0 与自身交换算有效移动 |
| 初始化就是通关棋盘 | 第 9 格确认后启动，通关标准为目标排列；未单列此场景 | 建议立即进入 WON，步数均为 0，再确认显示统计 |
| 非法状态保持时间 | 规定闪烁，未规定持续时间或频率 | 建议错误保留到下一次成功操作/有效恢复/复位；B 采用肉眼可辨闪烁节拍，参数可调 |
| 模式切换是否保留进度 | 允许选择模式，未规定跨模式保存 | 建议切换即清理当前游戏并重启所选模式，不实现双份存档 |
| 演示复位后模式灯 | 模式有独立 LED，但演示末步要求所有输出全灭 | 建议末步全局输出静默，保留内部模式选择，下一次明确开始操作后恢复 |
| 棋盘可解性 | 初始化合法性只规定 0～8 不重复，未要求判断排列可解性 | 不额外拒绝不可解排列；求解器、最优路径、多级撤回和随机出题均不列入官方必做任务 |
