# CS207 数字华容道项目框架说明


## 1. 依据与范围


框架按分工报告选择 EGO1 基础外设方案：拨码/按键输入，8 位数码管与 16 个 LED 输出。不加入 VGA、UART、手机 APP、求解器、多级撤回等扩展。

开发约定（2026-11-17 更新）：后续模块开发默认不新增或扩写 testbench、仿真脚本及专门的仿真验证报告，也不将这些文件作为交付前置条件。已有基础仿真文件与历史记录保留参考，仅在明确要求时再调整或运行。功能正确性仍需通过代码检查、联调和 EGO1 实机操作核对。

**这是供三人开始实现的工程骨架，不是完成版游戏。** 已建立端口、状态归属、顶层接线、约束和开发入口；游戏规则、显示驱动、输入处理和演示逻辑保留明确 TODO。现阶段板上输出保持全灭，核心不接受命令，以免把空壳误认为已有功能。

## 3. 模块怎么合作

```text
按键/拨码 → C 输入处理 → C 命令路由 → A 游戏核心
                              ↑            │
                          C 演示控制         │ 只读状态
                                           ↓
                                   B 提示 + B 显示排版
                                           ↓
                                   B 扫描 + 顶层 LED 映射
                                           ↓
                                       EGO1 输出
```

- A 只维护一份棋盘、阶段、计数、错误与历史。以 `cmd_valid/cmd_ready` 接受命令。
- B 读取状态，不修改棋盘；自行维护提示/统计的显示选择。通过固定状态即可独立开发。
- C 将真实输入与演示操作转换为同一套命令，负责顶层、约束和工程集成，不维护另一份演示游戏核心。

棋盘打包为 36 位：最高 4 位是左上角，最低 4 位是右下角，目标棋盘为 `36'h123456780`。命令编码与阶段编码集中在 `project_defs.vh`，详细语义见 `项目仓库/docs/interfaces.md`。

为落实原分工文件中的“演示可配置初始视图”，新增 `view_default_hint` 端口，与 `view_reset` 配合；普通游戏默认统计，演示可预置提示。该行为仍需团队核对官方奇偶次数要求。

## 4. 三人从哪里开始

| 成员 | 首先打开 | 最小闭环 |

任务细分与 F01～F18、E01～E11 的落点见 `docs/work_packages.md`。综合与实机集成时，各人负责修复自己模块的问题。

## 6. 如何运行

在 Vivado 命令环境中创建工程：

```text
vivado -mode batch -source scripts/create_project.tcl
```

生成 `build/vivado/puzzle_ego1.xpr`；默认器件 `xc7a35tcsg324-1`，设计顶层 `top`，仿真顶层 `tb_top`。未来新增源码时更新 `scripts/sources.tcl`。功能补全后 `scripts/build.tcl` 可运行综合；后续实现、DRC、时序和 bitstream 由 C 继续完成。

本次使用 Vivado/XSim 2018.3 完成 RTL 编译、模块展开、4 组基础仿真和工程重建，均通过；51 个 IO 的静态引脚覆盖与原约束对照也通过。详细结果与未执行项记录在 `项目仓库/docs/verification.md`。未运行综合、实现或上板功能验收。
