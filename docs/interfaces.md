# 模块接口契约 v0.1

状态：供三人开始开发的草案，尚未经过团队确认。公共编码仅在 `rtl/include/project_defs.vh` 定义。修改端口、宽度或语义时同时修改此文档、顶层和测试。

## 状态归属与数据流

```text
按键/拨码 -> input_frontend --+--> command_router --> game_core
                            |          ^                 |
                            +--> demo_controller         | board/phase/count/error
                                       |                 v
                                       +-------> hint_logic + display_frontend
                                                    | symbols + LEDs
                                                    v
                                                seg_scan / top -> 板卡
```

C 发命令，A 是棋盘与游戏统计唯一写入者，B 只读逻辑状态。B 的 `show_hint` 是显示选择状态，不是游戏状态。`top` 只接线和转换物理位序，不实现移动规则。

## 时钟和复位

全部模块使用 `clk` 上升沿和内部高有效 `rst`。顶层由 `reset_sync` 将板上复位异步置位、两拍同步释放；模块内部按同步复位编写。`RESET_ACTIVE_LOW=1` 为暂定板级参数，不能凭原约束中的 `sys_rst_n` 名称认定极性。

所有慢速逻辑用时钟使能，避免增加普通逻辑生成的时钟。按键、模式和拨码需由 C 同步并消抖/稳定采样；复位同步器不替代普通按键消抖。当前输入模块未实现这些功能。

## 核心命令 C → A

| 信号 | 宽度 | 约定 |
|---|---:|---|
| cmd_valid | 1 | C 声明存在待接收命令 |
| cmd_ready | 1 | A 声明本拍可接受命令 |
| cmd_kind | 3 | CLEAR=0、CONFIRM=1、UNDO=2、LOAD_DEMO=3；4～7 保留并忽略 |
| cmd_tile | 4 | 编号 0～15 均原样传入，由 A 判断合法性 |
| cmd_board | 36 | LOAD_DEMO 的完整棋盘，其余命令忽略 |

只在 `cmd_valid && cmd_ready` 的上升沿接受一次命令。等待期间保持 valid、kind、tile、board 稳定。C 在捕获用户事件时锁存拨码，不可让等待中的载荷随拨码变化。复位取消待处理命令。

仲裁优先级：复位 > 模式切换清理 > 撤回 > 当前模式确认/演示。已出现在接口上的命令不能因模式切换改变载荷：先完成该命令，再优先发 CLEAR；新的模式命令必须等 CLEAR 被接受。模式切换中的普通输入事件暂不受理；快速连续按键的排队容量与丢弃规则由 C 在实现时补充到此处。

`demo_valid/ready/kind/tile/board` 使用相同握手规则。路由器不得在没有实际接收/缓存请求时回报 demo_ready。`sequence_reset` 取消演示源当前序列；若路由器已接走旧命令，由路由器负责后续清理，不依赖演示源继续持有它。

## 核心状态 A → B/C

| 信号 | 宽度 | 约定 |
|---|---:|---|
| board | 36 | 第 i 格为 `board[35-4*i -: 4]`，i=0～8，按行排列 |
| filled_count | 4 | 已确认格数 0～9；不能用棋子为 0 判断未填 |
| phase | 2 | INIT=0、PLAY=1、WON=2、STATS=3 |
| init_error / move_error | 各 1 | A 维护错误状态；B 决定闪烁与显示 |
| valid_count / invalid_count | 各 CW | 默认 CW=4；溢出策略尚待确认 |
| undo_available | 1 | 存在一级历史时为 1；暂供测试/状态观察 |

复位/CLEAR：棋盘=0、filled_count=0、INIT、计数=0、错误=0、无历史。INIT 的 CONFIRM 逐格输入；非法输入不推进且不增加游戏无效计数。PLAY 的 CONFIRM 执行移动；通关先进入 WON 保留棋盘，WON 再 CONFIRM 才进入 STATS。LOAD_DEMO 初始化完整棋盘并清零计数、错误、历史，再进行通关判断。

建议撤回包含上一次有效或无效移动尝试，恢复棋盘、两类计数、阶段和错误，再消费历史；暂仅 PLAY 可用。此语义及溢出规则见 `decisions.md`，属于待确认方案。

## 显示控制 C → B

| 信号 | 约定 |
|---|---|
| view_toggle | 单周期切换脉冲 |
| view_reset | 单周期重新设置视图，优先于切换 |
| view_default_hint | view_reset 当拍采样；0=统计，1=提示。为分工文件“可配置初始选择”新增的明确端口 |
| demo_mode | 0=游戏，1=演示；由 C 维护 |
| advanced_active | 基础外设方案顶层恒接 0 |
| output_blank | 全部外部输出熄灭，包括模式灯、状态灯和数码管 |

硬件复位时视图选择为统计；正常游戏第一次切换为提示。演示入口拟用 `view_reset=1, view_default_hint=1` 配置初始提示，但与官方奇偶次数规则的关系待确认。

## B 内部接口和物理映射

- `hint_mask[7]` 对应棋子 1，`[0]` 对应棋子 8；未填满为全 0。提示按棋子编号，而非格子编号。
- `symbols[31-4*i -: 4]` 为从左到右第 i 个数码管字符，i=0～7。0～9 为数字，E 为错误，F 为空白。棋盘的 0 转换成 F；十进制统计的数字 0 则仍为 0。
- `info_leds[7:0]` 物理从左至右；统计时高四位为有效数，低四位为无效数。超出 15 的行为不在骨架中擅自决定。
- `tile9_leds[3:0]` 物理从左至右，最高位在左。
- `top` 将 `info_leds[7-i]` 接 `led_pin[i]`；将 `tile9_leds[3-i]` 接 `led_pin[8+i]`。索引规则已与提供的 XDC 对齐。
- `seg_data_*_pin[7:0] = {dp,g,f,e,d,c,b,a}`，段选与位选均高有效。两组段选不可合成一组；物理数字排列由 B/C 上板确认。

## 演示状态流程（待实现）

模式清理完成后自动加载第一幕，之后每按一次演示推进键推进一幕；只在命令被接受后推进状态。

| 幕 | 命令 | 预期棋盘 | 有效/无效 | 提示 mask |
|---|---|---|---|---|
| 1 | LOAD_DEMO，123456708 | 123456708 | 0/0 | 00001011 |
| 2 | CONFIRM，1 | 保持 | 0/1 | 00001011 |
| 3 | CONFIRM，8 | 123456780，WON | 1/1 | 00000101 |
| 4 | CONFIRM | STATS，棋盘数据保持 | 1/1 | 可保留 |
| 5 | CLEAR | INIT，所有输出灭 | 0/0 | 不显示 |

末幕的 `demo_blank` 在 CLEAR 接受后置位，再由 router 合并到 output_blank；退出/重新进入演示或复位后重启。第 3 幕按正式移动规则增加有效数，官方示例“无效步数+1”为已登记的疑似笔误。
